# Браузерная модель v2

Один и тот же DINOv2 Small INT8 обрабатывает четыре перекрывающиеся области кадра. Для каждой области модель нормирует глобальный вектор и средний вектор токенов. Затем усредняет признаки четырёх областей. Три линейные головы дают независимые оценки типа шкафа, МП и ЛКП. Один проход использует вход 224 × 224. Выбор областей фиксирован в рецепте.

## Сравнение

Обе версии проверены на одних и тех же 61 размеченном фото, 52 группах связанных кадров и пяти внешних фолдах для каждого seed. Порог выдачи метки 0,50. Основной seed 42 сохранён из первой версии.

## Воспроизведение

Старые веса голов сохранены в `heads.json`. Приложение загружает `heads-v2.json`. Для воспроизведения выполните команды из корня проекта с локальным доступом к разрешённым копиям данных.

```sh
./browser-ml/prepare_runtime.sh
python -m scripts.probe_browser_cabinet \
  --source /path/to/first-dataset --source /path/to/second-dataset \
  --report /tmp/browser-ml-oof.json
python -m scripts.train_browser_cabinet \
  --recipe local-average --source /path/to/first-dataset --source /path/to/second-dataset \
  --onnx browser-ml/runtime/dino-int8.onnx
```

В `oof-summary.json` находятся агрегированные метрики. Граф ONNX и WebAssembly остались прежними, около 36 МБ при первой загрузке. Фотографии и результаты по отдельным кадрам не входят в публичный отчёт.

В локальном E2E на Chromium с мобильным размером окна проверены два реальных JPEG. Максимальная разница между Python и WASM по двум дефектным оценкам составила 0,0086. Время двух осмотров составило 1,28 и 1,06 с против 0,82 и 0,61 с у исходной модели. Замер выполнен на одном компьютере через локальный сервер. Запрос крупного плана и второй осмотр сохранились после перезагрузки.
