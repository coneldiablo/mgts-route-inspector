# Маршрутный осмотр МГТС

[Открыть прототип](https://coneldiablo.github.io/mgts-route-inspector/) · [Распознать собственное фото](https://coneldiablo.github.io/mgts-route-inspector/predict/) · [Сопроводительная документация](docs/FINAL.md) · [Скачать публичную презентацию](https://github.com/coneldiablo/mgts-route-inspector/releases/tag/v0.2.0)

Система распознаёт распределительные щиты и телекоммуникационные шкафы. У одного объекта могут быть механическое повреждение и дефект покрытия одновременно. Мастер подтверждает каждую работу, запрашивает конкретный ракурс и принимает результат по фотографии. Браузерный прототип работает на собственном устройстве без учётной записи. Для работы команды доступен локальный сервер с SQLite и выгрузкой реестра.

Полный локальный ансамбль обработал 62 снимка из двух поставок финала. На 61 размеченном кадре в пяти групповых разбиениях среднее F1 по двум дефектам составило **0,694**, у базового метода **0,573**. Обнаружен хотя бы один признак на **35 из 41** повреждённого кадра. Ошибочные срабатывания были на **11 из 20** исправных кадров. Компактная браузерная модель оценена отдельно. [Протокол проверки и запуск](docs/FINAL.md)

## Предварительный этап проекта

Материалы ниже описывают ранний прототип маршрутного осмотра и отдельные эксперименты на люках.

Мастер получает очередь объектов для проверки после маршрутного осмотра. YOLO26n ищет люк на снимке, DINOv2 оценивает видимое состояние, а Gemini 4 Argon может перепроверять сложные кадры. Интерфейс показывает исходное фото, рамку, статус и привязку к реестру. Мастер подтверждает или отклоняет замечание и выгружает очередь.

## Работа с выданными данными

Импорт принимает CSV и XLSX. Он сверяет строки с папкой фотографий, формирует `manifest.csv` и показывает, сколько записей содержат ID, координаты и метки. Для XLSX установите пакет проекта с дополнением `excel`.

```bash
python -m pip install '.[excel]'
python -m inspector intake --data data/final --table data/final/observations.xlsx \
  --column 'image=Файл фото' \
  --column 'label=Вид повреждения' \
  --column 'source_status=Статус'
```

Замените названия справа от `=` на заголовки выданной таблицы. `label` используется при обучении и оценке. `source_status` хранит исходный статус для сверки. Если широта и долгота относятся к машине, укажите их как `camera_lat` и `camera_lon`. Для координат самого объекта используйте `lat` и `lon`.

Для запуска на выданном пакете выберите артефакт модели с подходящими классами. При наличии реестра передайте CSV с `asset_id`, `lat`, `lon` и, при наличии, `object_type` и `address`.

```bash
python -m inspector run --data data/final --artifact artifacts/final --out runs/final \
  --registry data/final/registry.csv --location-radius 30 --json
python -m inspector serve --run runs/final --artifact artifacts/final
```

Точное совпадение ID при согласованных данных подтверждает привязку к записи реестра. При наличии только GPS машины система предлагает объекты в заданном радиусе. Расстояние считается в метрах по формуле гаверсинусов. Мастер выбирает нужный объект по фото и реестру. Выбор сохраняется отдельно от решения о дефекте. Схема показывает объекты с установленными координатами, а GeoJSON сохраняет их точки и источник привязки. CSV и JSON содержат всю очередь, включая случаи, требующие сверки.

## Результат публичного демо

Сравнение выполнено по исходным классам `manhole` и `void`. В просмотренной выборке `void` встречаются колесо, стена и тротуар. Оснований трактовать этот класс как открытый люк нет. Метрика относится к отбору фотографий для ручной проверки. [Описание исходного набора](https://huggingface.co/datasets/delima87/manhole_covers_dataset)

На 275 отложенных фотографиях модель приняла 272 решения и запросила три повторных снимка. Пороги обеих моделей выбраны на обучающей части. Абсолютные числа, ошибки и ограничения приведены в [аудите проекта](docs/AUDIT.md).

## Что уже работает

- `manifest.csv` + папка изображений → проверка читаемости, резкости, света, масштаба.
- Сменные признаки с одним классификатором:
  - `hybrid` (по умолчанию при наличии torch) — предобученный `MobileNetV3-Small`
    (ImageNet, без дообучения) + явные цвето-текстурно-геометрические признаки;
  - `mobilenet_v3_small` — только CNN-эмбеддинги;
  - `classical` — простой baseline для честного сравнения и запуска без тяжёлых зависимостей.
  - `dinov2_small` и `dinov2_hybrid` — замороженные признаки DINOv2 с обучаемой классификацией.
- Режим поиска аномалий, если размечена только норма (запасная концепция № 10).
- OOF-оценка **по объектам**, а не по кадрам: без утечки соседних кадров.
- Одна карточка на объект и признак: повторы и несколько ракурсов не создают новые задачи.
- Явный отказ «нужен другой кадр»: размытие/темнота/малый масштаб не превращаются в замечание.
- Интерфейс мастера: очередь, кадр + кроп, bbox, основание, действие, подтверждение/отклонение,
  запрос кадра, экспорт CSV/JSON, загрузка нового файла «на лету».
- Синтетический стенд для проверки всей цепочки до выдачи реальных данных.

## Данные: минимальный контракт

`manifest.csv` в папке данных. Одна строка соответствует одному кадру. Один прогон объединяет кадры каждого объекта за один осмотр. Независимые визиты передавайте в разных прогонах.

| Колонка | Обязательна | Смысл |
|---|---|---|
| `image` | да | путь к файлу относительно папки данных |
| `asset_id` | желательно | ID физического объекта; без него берётся префикс `image_id` до `__` |
| `image_id` | нет | ID кадра; по умолчанию имя файла |
| `label` | для обучения | `normal`, `open_hatch`, `unusable` или свои классы |
| `object_type` | нет | `well`, `pole`, … (пока один тип на MVP) |
| `captured_at` | нет | ISO-время визита |
| `lat`, `lon` | нет | координаты объекта |
| `condition` | нет | день/ночь/влага/тень/перекрытие — для разбора ошибок |
| `bbox_x1…bbox_y2` | нет | область объекта в пикселях; без неё используется весь кадр |
| `criticality` | нет | 0…1, приоритет объекта из реестра |
| `source` | нет | `real`, `synthetic`, … |

Положительный класс задаётся названием: всё, что не `normal`, считается признаком для
очереди; `unusable` не учится и не оценивается как дефект. Для нескольких дефектов
классификатор многоклассовый, карточки строятся по каждому видимому признаку.

Проверить данные до обучения:

```bash
python - <<'PY'
from inspector.manifest import load_manifest
from collections import Counter
rows = load_manifest("data/demo")
print("кадров", len(rows), "объектов", len({r.asset_id for r in rows}))
print("метки", Counter(r.label for r in rows))
print("дубли кадров", len(rows) - len({r.image_id for r in rows}))
PY
```

## Как считается качество

- **Единица решения — объект в осмотре.** Несколько кадров одного `asset_id` и признака
  дают одну карточку; FP/FN считаются по объектам.
- **GroupKFold по `asset_id`.** Все кадры, ракурсы и аугментации объекта остаются в одной части.
- **Порог** выбирается на out-of-fold прогнозах: по умолчанию максимум F1; опционально —
  максимальная полнота при ограничении FPR (`--threshold-mode budget --max-fpr 0.10`).
- **Отказ не прячет пропуск.** Доля отказов и end-to-end recall с отказами показываются отдельно.
- **Сравнение с baseline.** `--compare` обучает ту же схему на классических признаках
  и сохраняет `comparison.json`.
- **Синтетика помечается везде.** Цифры на синтетике доказывают работоспособность механики,
  но не качество на реальных снимках МГТС.

После `train` смотрите:

- `artifacts/public/meta.json` — порог, классы, размер, CV;
- `artifacts/public/eval.md` — понятный отчёт для защиты;
- `artifacts/public/oof.csv` — все out-of-fold прогнозы;
- `artifacts/public/thresholds.csv` — компромисс полнота/ложные тревоги;
- `artifacts/public/comparison.json` — модель против baseline.

## Статусы карточки

| Статус | Когда | Что видит мастер |
|---|---|---|
| `finding` | кадр пригоден, `p ≥ порога` | признак, кадр, действие |
| `uncertain` | сигнал в узкой полосе ниже порога | «проверить вручную / нужен кадр» |
| `rephoto` | размыто, темно, мало разрешение/масштаб | причина отказа и запрос кадра |
| `normal` | кадр пригоден, сигнала нет | «действий не требуется» |

Повторы группируются по `(asset_id, признак)`. Лучший кадр выбирается по уверенности и
качеству, остальные остаются в истории. Приоритет — уверенность × серьёзность признака
+ критичность объекта; это эвристика, а не «вероятность аварии».

## Честные ограничения

1. **Перенос на маршруты МГТС предстоит проверить.** Публичные кадры имеют технические ID по одному на фото. Физические объекты и маршруты в них не идентифицированы.
2. **Один тип объекта и один признак** — осознанный MVP. Финальное ТЗ может потребовать
   несколько классов; схема поддерживает многоклассовость, но потребует данных.
3. **Локализатор обучен на люках.** Для опор и других объектов нужны данные с их рамками.
   В отчётах точность рамки и состояние люка измеряются отдельно.
4. **Перекрытие автомобилем** не всегда определяется эвристикой качества. В MVP такой кадр
   должен уходить в «неуверенно/нужен кадр» по низкой уверенности; это проверяется на данных.
5. **Порог и калибровка** требуют валидации на объектах, которых не было в обучении.
   Оценка модели не является вероятностью аварии.
6. **Внешние сервисы не используются.** Всё считается локально; правила передачи изображений
   третьим сторонам нужно уточнить у организатора.
