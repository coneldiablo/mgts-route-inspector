# Маршрутный осмотр МГТС

Эксперт может открыть [интерактивный сценарий](https://coneldiablo.github.io/mgts-route-inspector/) или сразу [распознать фотографию шкафа](https://coneldiablo.github.io/mgts-route-inspector/predict/). Для анализа подходит фото одного РЩ или ТКШ. Изображение обрабатывается на устройстве. Модель выдаёт две самостоятельные оценки — механического повреждения и повреждения лакокрасочного покрытия (ЛКП).

## Что показать на защите

1. В сценарии осмотра откройте шкаф с двумя замечаниями. Подтвердите каждую работу. На трёх реальных строках МГТС указаны оба вида повреждения.
2. Загрузите кадр с пограничной оценкой. При значении от 0,40 до 0,60 включительно карточка автоматически запрашивает пересъёмку по признаку, ближайшему к 0,50. Для механики это крупный план петель и креплений, для ЛКП — крупный план поверхности при рассеянном свете. Это правило очереди. Мастер также может запросить свой ракурс. Полученный снимок сохраняется в той же карточке.
3. В приёмке сопоставьте исходный снимок с фото результата. Примите работу по механике и оставьте открытой работу по покрытию. Пример в публичной витрине использует учебную иллюстрацию. В режиме «Распознать своё фото» тот же процесс проходит на ваших изображениях, карточки сохраняются в IndexedDB этого браузера. Если координаты шкафа известны, их можно ввести вручную и открыть точку на карте.
4. Для общего рабочего места запустите сервер ниже. Он хранит фото и решения в SQLite, принимает известные координаты самого шкафа и выгружает реестр CSV. В двух файлах поставки есть GPS съёмки. Местоположение оборудования требует отдельного подтверждения.

На кадре DSS-004 в разметке отмечены повреждения корпуса РЩ и покрытия. В отложенном прогнозе ансамбля оценки составили 0,746 и 0,841. Из трёх двудефектных примеров оба признака одновременно найдены на одном при пороге 0,5. Проверка закрывания двери — отдельное действие мастера.

## Проверка на двух поставках МГТС

Две поставки содержат шесть таблиц. 61 исходный кадр сопоставлен со строкой XLSX и ещё один кадр со стрелкой обработан отдельно. Среди размеченных кадров 20 без повреждений, 18 только с механическим повреждением, 20 только с повреждением ЛКП и 3 с обоими признаками. Модель получает только пиксели. Тип и признаки извлечены из разметки для обучения и оценки.

Для оценки связанные кадры объединили в 52 группы по визуальному сходству, данным съёмки, идентификаторам и проверенным вручную связям. Каждая группа целиком отложена в одном из пяти внешних разбиений. Внутри обучающей части каждого разбиения три внутренних разбиения выбирают признаки для каждой головы. Итоговый артефакт обучен на всех 61 размеченных кадрах. Оценка относится к этим данным, отдельной испытательной поставки с другого маршрута пока нет.

Полный ансамбль обнаружил механический дефект на 17 из 21, дефект ЛКП на 17 из 23. Признак повреждения ошибочно отмечен на 11 из 20 размеченных исправными кадров. Выбранная политика пометила 11 кадров кандидатами на ремонт (10 с реальным повреждением), 48 передала на проверку и 2 оставила без действий. Это правила очереди. Отдельных эталонных решений о назначении ремонта и подтверждённых пар до/после в поставке нет. Приёмку выполняет человек.

## Как устроены модели

Полный ансамбль использует предобученные зрительные кодировщики Google SigLIP 2, DINOv2 Small и MobileNetV3, несколько фрагментов кадра и классические признаки изображения. Отдельно для типа шкафа, механики и ЛКП отбираются три набора признаков, затем усредняются оценки логистических классификаторов. Порог 0,5 формирует замечание. Для кандидата на ремонт требуется пригодный кадр, оценка одного из дефектов от 0,80 и оценка типа от 0,60. Мастер определяет конкретную работу. Модель обучена на уровне кадра. Точные рамки дефектов и исправность двери по фото не измерялись.

В браузере DINOv2 Small INT8 дважды обрабатывает снимок, целиком и по центру, через ONNX Runtime WebAssembly. Линейные классификаторы обучены на признаках именно этого компактного кодировщика. Примерно 36 МБ статических ресурсов скачиваются при первом распознавании. Изображения и рабочие карточки остаются в браузере. Серверный ансамбль и браузерный вариант запускаются без биллинга, Vertex и API-ключей.

Предыдущая версия проекта содержит отдельный эксперимент YOLO26n + Gemini на люках. Его можно воспроизвести по [отчёту предварительного этапа](ML_BENCHMARK.md). Метрики выше измерены на официальных шкафах.

## Запуск ансамбля и рабочего места

Из корня репозитория выполните следующие команды. Проверенная версия Python — 3.13. Первый запуск загружает опубликованные предварительно обученные кодировщики. В репозитории уже есть обученные финальные головы.

```bash
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[cabinet,dev]'
python -m scripts.cabinet_final predict /путь/к/фото.jpg
python -m uvicorn inspector.field:create_app --factory --host 127.0.0.1 --port 8080
```

Откройте [рабочее место](http://127.0.0.1:8080/field) и загрузите фото. В интерфейсе можно добавить пропущенное замечание, приложить снимок с пересъёмки, принять одну работу и выгрузить CSV. По умолчанию данные сохраняются в `runs/field/inspections.sqlite3`. Папку задаёт `MGTS_FIELD_DIR`, путь к доверенному локальному артефакту — `MGTS_CABINET_MODEL`.

Чтобы воспроизвести обучение, укажите два каталога в порядке поставок ДСС, ДСС-2.

```bash
python -m scripts.cabinet_final train \
  --source '../Датасет-ДСС' --source '../Датасет-ДСС-2' \
  --reviewed-groups scripts/cabinet_groups.json
python -m pytest
```

Исходные фото, таблицы МГТС и SQLite рабочих осмотров хранятся у владельца данных. Файл `predictions.json`, формируемый локально при обучении, содержит пути к исходным файлам. Для открытого релиза подготовлены обезличенные результаты.
