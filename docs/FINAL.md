# Маршрутный осмотр МГТС

Система превращает фотографию распределительного щита (РЩ) или телекоммуникационного шкафа (ТКШ) в карточку работ. У шкафа может быть несколько замечаний. У каждого замечания есть собственные решение мастера, запрос ракурса и результат приёмки. [Распознать своё фото](https://coneldiablo.github.io/mgts-route-inspector/predict/) · [Интерактивный пример](https://coneldiablo.github.io/mgts-route-inspector/)

## Второе мнение Gemini 4 Argon

Рабочее место использует Google Vertex AI с ADC. Мастер явно выбирает отправку исходного кадра. Клиент убирает EXIF и передаёт только уменьшенное изображение и зафиксированный промпт. В карточке появляются независимые оценки, видимые признаки и сравнение по двум дефектам. Для смешанной оценки вес локальной модели равен 75%, вес Argon — 25%. Классификация типа остаётся локальной. При отсутствии ответа мастер продолжает с локальным прогнозом.

На основном разбиении, на всех 61 размеченных кадрах с локальным резервом, среднее F1 механики и ЛКП выросло с 72,29% до **81,78%**. Обнаружены 38 из 41 повреждений при 5 ложных тревогах на 20 исправных. На пяти вариантах группировки прибавка была положительной в каждом, в среднем **9,08 п.п.** В независимых результатах двух меток у смеси по-прежнему 1 из 3 верных двойных и 5 ложных двойных. При пороге 0,5 отдельный Argon на доступных 60 размеченных кадрах нашёл 3 из 3 двойных, а ещё на 8 кадрах ошибочно указал сразу два дефекта. Проверка мастером существенна.

Из 62 запросов получен 61 ответ, один завершился тайм-аутом. Медиана успешного ответа 6,77 с. Публичный реестр показывает сохранённые ответы. Для самостоятельного живого вызова в серверном окружении установите дополнение `vertex` и настройте Google Application Default Credentials для проекта с доступом к модели. ## Как показать на защите

1. Загрузите снимок одного шкафа. В карточке откройте оценку механического повреждения и оценку лакокрасочного покрытия (ЛКП). Кнопка «Показать фрагмент» выделяет ту из четырёх областей, которая внесла наибольший вклад в выбранную оценку. Область помогает осмотреть кадр. Точных контуров повреждения в разметке нет.
2. По каждому замечанию подтвердите или снимите работу. Можно добавить пропущенный признак. При оценке в интервале 0,40–0,60 система запрашивает крупный план для признака, ближайшего к 0,50. Для механики это петли и крепления, для ЛКП — поверхность при рассеянном свете. Мастер может заказать ещё один ракурс. Предыдущие запросы и снимки сохраняются.
3. В приёмке приложите результаты работ. Например, примите ремонт двери по одному снимку, а восстановление покрытия оставьте открытым по другому. Откройте фото, на основании которого принято решение, и сравните с исходным. Кнопка «Скачать акт осмотра» сохраняет автономный HTML с решениями, временем и фотографиями. Его можно распечатать или открыть без интернета. Исполнитель подтверждает соответствие объекта при добавлении кадра.
4. При известных координатах укажите положение шкафа и откройте точку на карте. В двух исходных файлах есть GPS камеры. Для записи положения самого шкафа требуется подтверждение.

На учебной витрине используется иллюстрация. В режиме распознавания мастер работает со своими фото, а карточки хранятся в IndexedDB этого браузера. Для общей очереди предусмотрено серверное рабочее место с SQLite и экспортом CSV.

## Проверка на двух поставках МГТС

Из шести таблиц удалось сопоставить 61 размеченный кадр. Ещё один снимок обработан без эталонной метки. В разметке 20 кадров без дефектов, 18 только с механикой, 20 только с дефектом покрытия и 3 с обоими признаками. Связанные изображения образуют 52 группы. Во внешней пятикратной перекрёстной проверке все кадры одной группы попадают в один фолд. Модель получает пиксели. Итоговые головы для рабочего места обучены на всех 61 размеченных кадрах.

| Основное разбиение, seed 42 | Простые признаки | Сервер v0.2 | Сервер v0.4 | Браузер v2 |
| --- | ---: | ---: | ---: | ---: |
| Среднее F1 механики и ЛКП | 57,25% | 69,39% | **72,29%** | **67,90%** |
| Найден хотя бы один признак на 41 повреждённом кадре | 34 | 35 | **36** | **37** |
| Ложная тревога на 20 исправных кадрах | 12 | 11 | **9** | **10** |
| Правильно определён тип шкафа из 61 | 38 | 43 | **48** | **42** |

На пяти заранее заданных вариантах разбиения среднее F1 двух дефектов выросло с **67,04% до 73,42%**. Ансамбль v0.4 улучшил показатель на всех пяти. Это повторная проверка на тех же снимках. Независимый маршрут остаётся следующей проверкой переноса. На основном разбиении групповой бутстреп даёт интервал изменения F1 от −4,0 до +9,7 п.п. На небольшом наборе величина выигрыша остаётся неопределённой.

Полный ансамбль обнаружил механику на 16 из 21 кадров (F1 71,11%) и дефект покрытия на 18 из 23 (F1 73,47%). На отложенном DSS-004 модель определила РЩ и дала оценки 0,784 для механики и 0,762 для покрытия. В целом оба дефекта вместе найдены на **1 из 3** двудефектных кадров при пороге 0,50. Назначение конкретной работы и проверка закрывания двери остаются за мастером.

В очереди по отложенным прогнозам 12 снимков получили приоритет «кандидат на ремонт», и на всех 12 в таблицах есть повреждение. В проверку направлено 47 кадров, в том числе остальные 29 повреждённых. Два исправных оставлены без действий. Класс состояния из XLSX позволяет оценить выявление повреждений. Правильность назначения ремонта и качество приёмки требуют отдельных экспертных решений и подтверждённых пар до/после.

## Как устроено распознавание

**Полный ансамбль.** Google SigLIP 2 So400m видит четыре перекрывающихся фрагмента шкафа, каждый в разрешении 384×384. Обученные логистические классификаторы оценивают два дефекта отдельно. Для каждой метки система усредняет результат новой модели и предшествующего ансамбля SigLIP 2, DINOv2 Small, MobileNetV3 и классических признаков. Равные веса использованы для всех пяти разбиений. Для определения типа Grounding DINO Tiny предлагает область шкафа. В 57 из 62 кадров была найдена область выше порога. При отсутствии подходящей области используется исходный кадр. Это число предложенных областей, точность детекции рамок не измерялась. [Эксперимент с крупными фрагментами](../runs/cabinet-hr-siglip/benchmark.json) · [Эксперимент с областью шкафа](../runs/cabinet-roi-grounding/benchmark.json)

Дополнительно проверили обучение по наиболее подозрительному фрагменту (multiple-instance learning). В среднем по пяти разбиениям F1 снизилось до 72,14%, число правильных двойных находок на основном разбиении осталось 1 из 3, а ложных двойных находок стало 5 вместо 4. В рабочей модели сохранено усреднение четырёх областей. [Протокол и результаты эксперимента](../runs/cabinet-mil/public-benchmark.json)

**Модель в браузере.** DINOv2 Small INT8 анализирует четыре перекрывающиеся области через ONNX Runtime WebAssembly. На основном разбиении переход от старой схемы к четырём областям повысил F1 с 58,52% до 67,90%. При первом запуске скачивается около 36 МБ. Фото обрабатывается на устройстве. Проверка читаемости пропустила 61 из 61 исходных кадров и выявила 39 из 61 искусственно сильно размытых. Все варианты с экстремальным затемнением, пересветом, однотонной заливкой или слишком малым разрешением получили запрос на пересъёмку. Контроль качества выполняется и при прикреплении подтверждающего снимка. [Сравнение компактных моделей](../browser-ml/MODEL-REPORT.md) · [Проверка читаемости](../browser-ml/input-quality-report.json)

**Предварительный этап.** YOLO26n и Gemini 4 Argon использовались в отдельном эксперименте на люках. Финальные модели для шкафов работают без внешнего API и облачных ключей. [Результаты предварительного этапа](ML_BENCHMARK.md)

## Запуск ансамбля и рабочего места

Из корня репозитория выполните команды для Python 3.13. Репозиторий содержит обученные головы. Команда подготовки скачивает публичные кодировщики и сверяет контрольные суммы.

```bash
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[cabinet,vertex,dev]'
python -m scripts.cabinet_final prepare
python -m scripts.cabinet_final predict /путь/к/фото.jpg
python -m uvicorn inspector.field:create_app --factory --host 127.0.0.1 --port 8080
```

Откройте [рабочее место](http://127.0.0.1:8080/field). Данные сохраняются в `runs/field/inspections.sqlite3`. Папку задаёт `MGTS_FIELD_DIR`, доверенный локальный артефакт — `MGTS_CABINET_MODEL`. Для облегчённой конфигурации используйте `prepare --without-hr` в среде без весов So400m. Источник оценки отображается в карточке. Список команд для воспроизведения полного обучения из двух поставок приведён в [инструкции по обучению](TRAIN_CABINET.md).

## Какие исследования повлияли на продукт

- Пилот FirstEnergy со служебными автомобилями помог сформулировать задачу приоритизации. В нашем случае операционный результат можно проверить по составу очереди из отложенных прогнозов. [Первичный источник FirstEnergy](https://www.firstenergycorp.com/newsroom/featured_stories/cameras-with-ai-aim-to-enhance-electric-service-reliability.html)
- В WinCLIP изучается вклад локальных окон в выявление аномалий, а работа Ding и соавторов исследует обнаружение дефектов люков. Для шкафов мы отдельно проверили эффективность нескольких перекрывающихся фрагментов. В браузере мастер может открыть наиболее влиятельный фрагмент для каждого признака. [Публикация WinCLIP, CVPR](https://openaccess.thecvf.com/content/CVPR2023/papers/Jeong_WinCLIP_Zero-Few-Shot_Anomaly_Classification_and_Segmentation_CVPR_2023_paper.pdf) · [Публикация в Sensors](https://www.mdpi.com/1424-8220/25/13/4144)
- Сценарии контроля полевых работ Nokia послужили ориентиром для приёмки. В нашей карточке решение связано с конкретным фото результата и отдельным замечанием. [Nokia Broadband Easy](https://www.nokia.com/broadband-access/services/broadband-easy/)
