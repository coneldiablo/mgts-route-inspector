# Аудит проекта МГТС · 25 ноября 2026

Публичное демо готово для показа отбора фотографий по видимости крышки. Команда может показать рабочую очередь, запрос повторного кадра, ошибку модели и решение мастера. Для заявления о распознавании открытых люков на маршруте нужна отдельная проверка с полевой разметкой.

## Что обнаружилось при просмотре фотографий

Поставщик публикует два класса, `manhole` и `void`, без инструкции разметчика. Проект переводил `void` в `open_hatch`. Просмотр 12 случайных изображений каждого класса из отложенной части (pandas, random_state=123), пяти ошибок и трёх отказов выявил несоответствие. Например, в классе `void` видны колесо автомобиля, стена, тротуар и рельсы. Такие метки не подтверждают открытый проём. [Карточка поставщика](https://huggingface.co/datasets/delima87/manhole_covers_dataset)

В обновлённом манифесте `source_label` сохраняет исходную метку. Публичная модель выдаёт запрос «Проверить видимость крышки» для класса `unconfirmed_cover`. Синтетические и полевые манифесты со своей разметкой могут по-прежнему использовать `open_hatch`. Старые публичные прогоны с прежней трактовкой распознаются при открытии. [Пример фото с колесом](../data/real_holdout/images/MHH-00239.jpg) · [Пример с крышкой](../data/real_holdout/images/MHH-00109.jpg)

## Как проверяли

В исходном архиве все 70 файлов `test/void` побайтно совпали с файлами обучения. Для основного сравнения взяли стратифицированное разбиение исходной обучающей части с seed 7. Получилось 2011 фотографий для обучения и 275 для проверки. В обучении прошли контроль качества 2000 фото, из них 949 класса `void`. Порог каждой модели выбран по F1 на пяти групповых разбиениях обучающей части.

Между обучением и каждой из двух проверочных частей одинаковых декодированных RGB-изображений не найдено. Дополнительно сравнили 64-битные dHash, построенные из 9×8 полутоновых изображений. Пар с расстоянием Хэмминга до четырёх включительно не найдено. В источнике отсутствуют надёжные ID физических люков и маршрутов. Эти проверки оставляют открытым вопрос о съёмке одного места с разных ракурсов.

## Результат на 275 отложенных фото

Положительным считается исходный класс `void`. 272 фото пригодны для классификации, три получили запрос повторной съёмки из-за низкого контраста. Все три имеют метку `void`. Precision, recall и F1 в таблице рассчитаны на 272 пригодных фото. В последнем столбце отказы входят в знаменатель.

| Модель | Порог | TP / FP / FN / TN | Precision | Recall | F1 | Сквозная полнота |
|---|---:|---:|---:|---:|---:|---:|
| MobileNetV3-Small + классические признаки | 0,47 | 127 / 4 / 1 / 140 | 96,95% | 99,22% | 98,07% | 127/131 = 96,95% |
| Классические признаки | 0,45 | 125 / 15 / 3 / 129 | 89,29% | 97,66% | 93,28% | 125/131 = 95,42% |

У гибрида 95%-й интервал Уилсона для precision составляет 92,41–98,81%, для recall — 95,71–99,86%. На этой подборке гибрид отправил на проверку на 11 меньше снимков с меткой `manhole` и нашёл на два больше с меткой `void`. [Отчёт гибрида](../artifacts/public/eval_holdout.md) · [Отчёт базовой модели](../artifacts/public/baseline/eval_holdout.md)

**Отдельная проверка переноса.** В авторском тесте осталось 70 уникальных фотографий `manhole`. При том же пороге гибрид лишний раз отправил на проверку 16 из 70 (22,9%), базовая модель — 20 из 70 (28,6%). Для сравнения, у гибрида в основной отложенной части было 4 таких решения на 144 фото `manhole` (2,8%). Разброс важен для прогноза нагрузки мастера. Измерить полноту на дополнительной части невозможно, поскольку в ней один класс. [Дополнительный замер гибрида](../artifacts/public/eval_official_normal.json) · [Замер базовой модели](../artifacts/public/baseline/eval_official_normal.json)

**Ошибки для разбора на защите.** На MHH-00183 виден тёмный прямоугольный элемент. При метке `manhole` модель дала классу `void` оценку 0,992. На MHH-00246 видны предметы в траве. При метке `void` модель дала этому классу 0,385 и пропустила кадр. MHH-00066 показывает другой исход — изображение слишком малоконтрастно для вывода. [Лишний запрос](../data/real_holdout/images/MHH-00183.jpg) · [Пропуск](../data/real_holdout/images/MHH-00246.jpg) · [Отказ по качеству](../data/real_holdout/images/MHH-00066.jpg)

## Что исправлено в проекте

| Участок | Исправление и значение |
|---|---|
| Загрузка данных | Контрольные суммы для обоих ZIP, временные файлы при скачивании и подготовке, проверка готовых разбиений перед повторным запуском. Фотографии прежней публичной версии остаются на месте при обновлении меток. |
| Манифест и обучение | ID сохраняют ведущие нули, дубли ID и пропущенные пути выявляются до обучения. При невозможности получить независимый OOF-прогноз модель сообщает о недостатке данных. Для режима ограничения FPR используются значения до округления. |
| Проверка качества | Метрики по фото и по объектам хранятся отдельно. Отказы учитываются в сквозной полноте. Оценка использует настройки кадрирования и фильтра из модели. Проверяются пересечения по ID и точные копии изображений для новых артефактов. |
| Пакетный прогон | Инференс идёт порциями. Непригодный кадр сохраняется с причиной отказа и без оценки класса. При наличии пригодного кадра того же осмотра отказ остаётся в истории. Имена копий различаются и при кириллических ID. |
| Интерфейс и решения | Исходное изображение при загрузке анализируется до JPEG-превью. Веб-анализ использует рабочий порог прогона. Предпросмотр порога описывает сохранённые кадры. Решения мастера привязаны к версии модели, доказательствам и настройкам. Служебные файлы исключены из раздачи медиа. |
| Сборка и показ | Исправлены команды запуска, состав wheel, описание модели и сценарий защиты. Проверено открытие готовой очереди в браузере. |

В итоговом прогоне 275 карточек. В очередь попало 135, включая 131 с результатом выше порога, один слабый сигнал и три запроса кадра. Проверены ссылки на все 550 кадров и фрагментов, формирование CSV и JSON и сохранение решений. Пакетная обработка с созданием превью заняла 4,95 с на этом ноутбуке при двух потоках CPU. [Сводка прогона](../runs/public/summary.json)

## Воспроизведение

Из корня проекта с активированным окружением и установленными зависимостями:

```bash
export TORCH_HOME="$PWD/artifacts/torch-cache"
export OMP_NUM_THREADS=2
python scripts/fetch_public_manholes.py
python -m inspector demo --backbone hybrid
python -m inspector serve --run runs/public --artifact artifacts/public
```

При обычном запуске основное сравнение записывается в `artifacts/public/eval_holdout.md` и в такой же файл в `baseline/`. Для отдельного авторского теста вызовите `evaluate_holdout(artifact_dir, "data/real_official_test", write=False)` из `inspector.evaluate`. Это сохраняет основной отчёт. Тесты запускаются командой `python -m pytest -q`. Пройдены 12 тестов, включая режим обучения только на норме, совпадение оценки в веб-интерфейсе и пакетном запуске, повторы кадров и полностью непригодную тестовую выборку. Проверены синтаксис JavaScript и сборка wheel вместе с HTML, CSS и JS. На отдельном синтетическом прогоне обработаны 118 кадров 48 объектов с поддержкой `open_hatch`. [Синтетический прогон](../runs/synthetic/summary.json)

## Что ещё требует проверки

- Для точности по открытым люкам нужны размеченные примеры открытого проёма, штатной крышки, перекрытия и плановых работ. Сохраните физический ID, визит и маршрут, чтобы проверить перенос на отложенные объекты и районы.
- Одна папка обрабатывается как один осмотр. Для сравнения состояния одного колодца в разные даты нужны отдельные прогоны. В публичной коллекции на каждый технический ID приходится одно фото.
- По публичным данным нельзя установить экономию времени мастера или приемлемое число проверок за смену. Для пилота нужно замерить время и лишние карточки на реальном потоке с естественной долей дефектов.
