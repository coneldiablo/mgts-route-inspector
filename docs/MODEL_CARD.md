# Model card: очередь объектов по видимому признаку

Версия 0.1.0 · прототип для финала МГТС · 25 ноября 2026

## Назначение

Публичная модель сортирует фотографии по видимости крышки. Обучающая метка `normal` соответствует исходному классу `manhole`. Обучающая метка `unconfirmed_cover` соответствует `void`. По такому снимку мастер проверяет ракурс и при необходимости просит переснять объект. Присутствие крышки само по себе также не подтверждает её исправность.

Отдельный каскад для подтверждённых примеров `open_hatch` использует YOLO26n для локализации, DINOv2 для состояния и опциональную перепроверку Gemini 4 Argon. Результаты проверки на публичных фото открытых и закрытых люков приведены в [отчёте ML](ML_BENCHMARK.md).

## Вход и выход

- Вход: RGB-кадр (JPEG/PNG), опционально bbox объекта, ID объекта и визита.
- Выход: `p_finding` (оценка модели), предсказанный видимый класс, статус
  `finding / uncertain / rephoto / normal`, причина и предлагаемое действие.
- `p_finding` — не калиброванная вероятность аварии. Порог — продуктовое решение,
  выбранное по допустимой нагрузке на мастера.

## Архитектура

1. **Проверка кадра:** разрешение, дисперсия лапласиана (резкость), средняя яркость,
   контраст, доля кадра под объектом (если есть bbox). Проверка не «понимает» перекрытие —
   это ограничение, а не обещание.
2. **Кроп:** bbox с отступом 8%. Для общего плана рамку может найти YOLO26n. Отдельный режим для одного известного целевого люка допускает запасную модель полного кадра.
3. **Признаки:** основной вариант — `hybrid`: `MobileNetV3-Small` с весами ImageNet
   (слой классификатора заменён на identity → 576-мерный эмбеддинг) плюс 222 явных
   цвето-текстурно-геометрических признака. Backbone не дообучается. Отдельно доступны
   `mobilenet_v3_small` (только CNN) и `classical` (только CV baseline); текущий
   демо-артефакт — `hybrid`.
4. **Классификатор:** `StandardScaler` + `LogisticRegression(class_weight="balanced")`.
   При нескольких дефектах — многоклассовый; `p_finding = 1 − P(normal)`.
5. **Порог:** OOF-таблица из 101 значения. По умолчанию максимум F1; альтернатива —
   максимальная полнота при FPR ≤ заданного (`budget`).
6. **Группировка:** по `(asset_id, видимый признак)`. Лучший кадр — максимум
   `p_finding` и качества; остальные кадры остаются историей, дубли не создают карточки.
7. **Fallback:** если размечена только норма — банк эмбеддингов и расстояние до
   ближайших нормальных объектов (идея PatchCore, без масштабной реализации).

Каскад для открытых люков использует `dinov2_hybrid`. Gemini помогает с трудными кадрами, когда включена перепроверка. Артефакт и порог детектора подбираются независимо от модели состояния.

## Данные и разбиение

- Одна строка manifest = один кадр. Один осмотр может включать несколько кадров объекта. Разные осмотры обрабатываются отдельными прогонами.
- Обучение — только кадры с меткой, прошедшие проверку качества; `unusable` исключается.
- **GroupKFold по `asset_id`**, чтобы кадры одного колодца не оказались в train и test.
- OOF-прогнозы используются и для порога, и для отчёта. Официальный тест — отдельно.

## Метрики

| Метрика | Смысл |
|---|---|
| Precision / Recall / F1 по объектам | основное качество очереди |
| TP/FP/FN/TN по объектам | абсолютные числа, не только проценты |
| Лишних карточек на 100 объектов | нагрузка на мастера |
| Top-10 precision и lift | полезность первых карточек |
| Покрытие и доля отказов | сколько кадров система честно не оценивает |
| End-to-end recall | отказы считаются пропусками, а не прячутся |
| ROC-AUC / AP | техническое качество ранжирования, не эффект |
| Время на кадр | реализуемость на ноутбуке |

Отчёт генерируется в `artifacts/<name>/eval.md`; исходные числа — `eval.json`, `oof.csv`.

## Проверка на публичных фото

В обучающей части 2011 фотографий. Проверку качества прошли 2000. На 275 отложенных фото сравнили гибридную модель и классические признаки, применив к каждой модели её заранее выбранный порог. Единица проверки — фото. Исходный набор не содержит надёжных идентификаторов физических объектов. Результаты и примеры ошибок приведены в [отчёте аудита](AUDIT.md).

## Ограничения и режимы отказа

1. **Домен:** синтетические крышки не равны реальным колодцам, ракурсам и погоде.
2. **Поиск объекта:** малые, боковые и множественные цели усложняют локализацию. Метрики поиска и состояния измеряются отдельно.
3. **Перекрытие:** машина/листва могут закрыть признак; модель может ошибиться.
   Правильное поведение — низкая уверенность → запрос кадра, но это надо проверить.
4. **Определение класса:** открытая крышка при плановых работах — не дефект. Карточка
   должна содержать контекст наряда; без него приоритет не повышается автоматически.
5. **Баланс:** при редком дефекте доля ложных тревог в эксплуатации будет выше, чем
   на искусственно сбалансированной выборке.
6. **Порог:** выбран на OOF; перенос на новый район/сезон требует повторной валидации.
7. **Один кадр:** фото сверху не показывает состояние кабеля; не обещать диагностику сети.

## Человек в контуре

Мастер подтверждает, отклоняет или запрашивает кадр. Все решения пишутся в SQLite с
комментарием и временем. Система не создаёт наряд на ремонт автоматически. Повторный
кадр дополняет карточку, а не создаёт новую задачу.

## Приватность и зависимости

- По умолчанию инференс выполняется локально. Явный флаг `--cloud-review` отправляет отдельные проблемные кадры или кропы в настроенный проект Vertex AI через ADC.
- Веса ImageNet скачиваются один раз при наличии сети; при отсутствии — классический
  baseline. На финале зависимости и веса нужно принести с собой.
- Лицензии: torchvision (BSD), scikit-learn (BSD), FastAPI (MIT), Pillow (HPND).
  Условия использования весов ImageNet и данных МГТС уточнить у организатора.

## Что должно быть проверено на реальных данных

- Различим ли признак на реальном масштабе и ракурсе.
- Есть ли независимые объекты для train/validation/test.
- Сколько положительных объектов, а не кадров.
- Насколько часты перекрытия, ночь, дождь, блики.
- Какая нагрузка ложных карточек приемлема для мастера.
- Не является ли открытая крышка штатным этапом работ.
