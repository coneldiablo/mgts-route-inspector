# Маршрутный осмотр глазами диспетчера и мастера

По брифу финала бригада Департамента сетевого сервиса за выезд посещает несколько площадок и проезжает 20–100 км. У подразделения уже есть маршрут для сбора наблюдений. Проблема в том, что сотрудник не может по пути осмотреть всю инфраструктуру. Результатом рейса должен стать понятный перечень объектов для проверки или ремонта.

| Кто работает | Что делает в прототипе | Что получает следующий сотрудник |
| --- | --- | --- |
| Экипаж | Загружает кадры одного рейса. Ошибка чтения отдельного снимка не останавливает обработку остальных. | Реестр всех входных кадров, включая запросы на пересъёмку |
| Диспетчер | Фильтрует состояния и рекомендации, открывает основания, уточняет ID оборудования и известные координаты шкафа. | Одну карточку осмотра с отдельными работами по механике и покрытию |
| Мастер | Смотрит исходное фото и наиболее влиятельный фрагмент, заказывает конкретный ракурс, подтверждает или снимает каждое замечание. На сервере может запросить второе мнение Gemini 4 Argon. | Список подтверждённых работ и история уточняющих фото |
| Сотрудник по приёмке | Сопоставляет фото до и после, принимает каждую работу отдельно или оставляет её открытой. | Акт осмотра с основаниями и фотографиями. В реестре собственного рейса видны решения мастера |

## Что открыть на защите

1. [В реестре набора](https://coneldiablo.github.io/mgts-route-inspector/registry/) показать все 62 кадра двух поставок. На 61 есть эталон, ещё один обработан без него. В итоговой выгрузке после обучения 36 кандидатов на ремонт, 11 проверок и 15 без действий. На карточке размеченного кадра отдельно доступен прогноз, полученный при его исключении из обучения. Публичные номера относятся к кадрам данной выгрузки.
2. [В распознавании](https://coneldiablo.github.io/mgts-route-inspector/predict/) выбрать несколько своих фото и название рейса. Открыть одну из созданных карточек. Ввести известный инвентарный номер, проверить два замечания, запросить при необходимости новый ракурс.
3. Для показа живого облачного запроса открыть локальное рабочее место, загрузить фото и нажать «Второе мнение Gemini Argon». В статическом публичном прототипе показаны сохранённые ответы реального прогона. Вычисление двух оценок DINOv2 на собственном фото доступно всем посетителям прямо в браузере.
4. По фото после ремонта подтвердить одну работу, вторую оставить открытой. Скачать автономный HTML-акт. Сохранить реестр собственного рейса в CSV. Он содержит состояние по фото, рекомендацию, решения мастера, подтверждённые координаты при наличии и время обработки каждого файла на данном устройстве.

## Что можно измерить в пилоте

Диспетчер вручную разбирает один набор поездок, а второй специалист независимо разбирает те же кадры с прототипом. Для следующих поездок они меняются ролями. Маршруты для пилота откладывают до настройки моделей. Старший мастер по выборке осмотров подтверждает состояние на месте или по дополнительным фото, включая часть объектов, которые система сочла исправными.

| Показатель | Как посчитать |
| --- | --- |
| Время разбора 100 кадров | 100 × активные минуты диспетчера / число просмотренных кадров. Сравнить два способа работы на одних поездках. Время вычисления из CSV проанализировать отдельно. |
| Полнота по повреждённым объектам | Число подтверждённых повреждённых объектов, которые попали на проверку или ремонт, / общее число подтверждённых повреждённых объектов контрольной выборки. |
| Повторный выезд за недостающими сведениями | Число нарядов, где бригаде понадобился повторный выезд именно для уточнения, / число завершённых нарядов. Причину и ID наряда фиксирует диспетчер. |
| Доказательства приёмки | Число принятых работ с ID объекта, отдельным решением и фото результата / общее число принятых работ. Спорные результаты проверяет старший мастер. |

Показатели описывают план пилота. В конкурсной поставке нет журналов поездок, рабочего времени и закрытия нарядов для расчёта фактической экономии.

## От фото к камере на служебном автомобиле

В пилоте кадры поступят с временем съёмки и треком машины. Из серии соседних кадров выбираются читаемые наблюдения. Положение камеры и направление обзора позволяют подобрать кандидатов в реестре оборудования. Несколько наблюдений объединяются только после сопоставления с объектом. При неоднозначности диспетчер уточняет ID или положение. После поездки система передаёт на согласование реестр с подтверждёнными объектами и открытыми вопросами. Сейчас прототип принимает готовые кадры. Геометку камеры нельзя считать координатой шкафа.

## Откуда взяли продуктовые решения

- **FirstEnergy.** В одном из пилотов компания закрепила камеры на машинах инспекторов и направляла отмеченные признаки повреждений опор на дополнительный осмотр. Мы перенесли принцип первичного отбора по штатному маршруту на РЩ и ТКШ из поставки МГТС. В очереди сохраняется информация о каждом признаке. [Публикация FirstEnergy](https://www.firstenergycorp.com/newsroom/featured_stories/cameras-with-ai-aim-to-enhance-electric-service-reliability.html)
- **Nokia Broadband Easy.** Nokia описывает визуальную проверку качества полевых работ. В нашем сценарии мастер связывает решение по каждому повреждению с отдельным снимком и может принять работу по двери, оставив покрытие в ремонте. [Описание Nokia](https://www.nokia.com/broadband-access/services/broadband-easy/)

Роли сотрудников и диапазон пробега взяты из выданной постановки задачи. Структура карточки, схема пилота и правила очереди предложены командой. Фактические потери времени в подразделении требуют измерения.
